# 폼체커 iOS — 기능 명세서

> **범위**: 사용자가 보는 기능 — 화면·흐름·문구·설정·기록
> **판정 알고리즘과 임계값은 이 문서가 아니라** [04_판정엔진_포팅명세.md](04_판정엔진_포팅명세.md)에 있다.
> **기준**: Android `79ef0bb` (2026-09-02)의 구현 동작 · 작성일 2026-11-20

---

## 0. 읽는 법

- **FR-xxx** = 기능 요구사항. iOS가 반드시 구현해야 한다.
- **AC** = 수용 기준. 그 요구사항이 됐는지 판단하는 문장.
- 🔁 = Android 동작 그대로 (판단 재고 금지 — 그렇게 된 이유가 Android 문서에 기록돼 있다)
- 🆕 = iOS에서 새로 정하는 것 (Android에 없거나 플랫폼 때문에 달라짐)
- ⚠ = 이식할 때 틀리기 쉬운 자리

## 1. 화면 지도

```
Splash ─▶ (첫 실행) Onboarding 4쪽 ─▶ Home ─┬─▶ Workout ─▶ SessionSummary
                                            ├─▶ History ─▶ SessionSummary
                                            └─▶ Settings
```

Android에 있는 개발용 2화면(`WorkoutLab` · `Capture`)은 iOS 1.0 범위 밖이다
([PRD §4.2](01_PRD.md#42-범위-밖-out-of-scope)).
다만 **Capture가 만들던 CSV/JSONL 포맷은 검증 도구로 따로 구현한다** (PRD §8).

### FR-NAV-01 🔁 나가는 자리는 **모든 화면에서 좌상단 아이콘 하나**다

제목도 같은 줄에 둔다. 화면이 자기 패딩 **밖·스크롤 밖** 최상단에 놓아야 좌표가 맞는다.
카메라 화면은 같은 아이콘을 HUD 위에 얹는다.

> ⚠ **하단 전체폭 `뒤로` 버튼을 다시 만들지 않는다.** Android에서 화면마다 나가는 자리가
> 달라 매번 찾아야 했던 문제를 고친 결과다.
> 🆕 iOS에서는 **스와이프 백 제스처가 기본으로 붙는다.** 운동 화면에서는 반드시 막아야 한다
> (실수로 세션이 날아간다 — FR-WRK-20 참고).

### FR-NAV-02 🆕 화면 방향은 **세로 고정**

Android 매니페스트는 방향을 잠그지 않았지만, 카메라 프리뷰의 3:4 가정과 HUD 레이아웃이
세로를 전제한다. iOS는 `Info.plist`에서 세로만 허용한다.

## 2. 공통 규칙

### FR-CMN-01 🔁 용어를 쓰지 않는다

| 쓰지 않음 | 대신 |
|---|---|
| rep 14회 | **14번** |
| 패럴렐 | 엉덩이가 무릎 높이 |
| valgus | 무릎이 안쪽으로 모임 |
| 깊이 부족 / SHALLOW | 얕음 / 덜 앉음 |
| SIDE / FRONT | 옆에서 / 앞에서 |
| 동기화 대기 | 업로드 대기 |
| 판정 불가 | 확인 못 함 |
| 짚은 횟수 | 피드백 횟수 |

⚠ **enum 이름이 화면에 그대로 나가지 않는지 확인한다.** Android에서 실제로 `SIDE`·`SHALLOW`가
찍혀 나간 적이 있다.

### FR-CMN-02 🔁 임계값 숫자를 문구에 넣지 않는다

"45°보다 기울었습니다"는 사용자가 확인할 수 없는 값이다. **무엇을 어떻게 바꾸라는 말만** 쓴다.

### FR-CMN-03 🔁 말투는 트레이너가 회원에게 하듯

존댓말, 지시가 아니라 제안("~해 보세요", "~해볼까요"). **없는 근거를 만들지 않는다** —
문제가 없을 때도 "자세가 좋아요"가 아니라 "따로 드릴 피드백은 없었어요"다.

### FR-CMN-04 🔁 용어 매핑은 한 곳에 둔다

Android `FeedbackLabels`에 해당하는 타입 하나를 만들고 **운동 중 화면·결과 화면·기록 화면이
함께 쓴다.** 같은 것을 두 화면이 다르게 부르면 안 된다.

### FR-CMN-05 🔁 다크 단일 테마 고정

시스템 라이트/다크 설정을 따르지 않는다. 🆕 iOS는 `.preferredColorScheme(.dark)` 고정.

### FR-CMN-06 🔁 색만으로 상태를 구분하지 않는다

Success(라임) / Warning(오렌지) / Danger(빨강) 배지·배너에는 **항상 아이콘을 함께** 둔다.

## 4. Onboarding (설치 첫 실행 4쪽)

| ID | 요구사항 |
|---|---|
| FR-ONB-01 🔁 | 4쪽 구성. 핵심 메시지: ① 카메라가 자동으로 센다 ② 기준 자세를 잰 뒤부터 센다 ③ 한 동작이 끝날 때 화면·소리로 알려준다 ④ 네트워크 없이 동작한다 |

## 5. Home (대시보드)

Android 순서를 그대로 쓴다: **오늘의 목표 → 운동 시작 → 이번 주 7일 막대 → 주간 합계·추정 열량 → 기록 → 설정**.

### 5.1 오늘의 목표

| ID | 요구사항 |
|---|---|
| FR-HOME-01 🔁 ⚠ | **하루 목표에 기본값이 없다.** 정하지 않았으면 `nil`이고, 앱이 임의의 숫자를 사실처럼 보여주지 않는다 |
| FR-HOME-02 🔁 | 목표가 없으면 `목표 정하기`, 있으면 진행률·남은 횟수(`목표까지 N회 남았어요` / `목표를 N회 넘겼어요`) |
| FR-HOME-03 🔁 | 목표 범위 1~500회, 조절 단위 5 |
| FR-HOME-04 🔁 | 지난 날도 **현재 목표 기준**으로 표시하고, 그 사실을 문구로 밝힌다 (`지난 날들도 지금 목표(N회) 기준으로 표시해요`) |

### 5.2 이번 주 막대그래프

| ID | 요구사항 |
|---|---|
| FR-HOME-05 🔁 ⚠ | **주는 월요일에 시작한다.** 날짜 경계 계산은 순수 함수 하나(`weekWindowOf(now, zone)`)에 둔다 — 화면에서 계산하지 않는다 |
| FR-HOME-06 🔁 ⚠ | 세션은 **시작 시각의 날짜**로 센다 (종료 시각 아님) |
| FR-HOME-07 🔁 ⚠ | 집계는 ViewModel이 끝내고 화면은 그리기만 한다. **rep 행을 홈으로 끌어오지 않는다** — DB는 주 범위만 잘라 세션별 횟수를 낸다 |
| FR-HOME-08 🔁 | 막대를 누르면 그 날이 선택된다(기본: 오늘). 기록이 없으면 `이 날은 기록이 없어요` |
| FR-HOME-09 🔁 | 주간 합계는 `총 N회` + `N일 운동` |

### 5.3 추정 소모 열량

| ID | 요구사항 |
|---|---|
| FR-HOME-10 🔁 | **선택한 날 하루치 + 이번 주 합계**를 함께 보여준다 |
| FR-HOME-11 🔁 ⚠ | 키·몸무게가 없으면 **0이 아니라 설정으로 가는 길**을 준다 |
| FR-HOME-12 🔁 | 나이·성별이 없으면 30세·남성으로 가정하고 **그 사실을 화면에 밝힌다** |
| FR-HOME-13 🔁 | 저장하지 않고 **볼 때마다 계산한다** |

### 5.4 문구

| ID | 요구사항 |
|---|---|
| FR-HOME-14 🔁 ⚠ | **홈 문구에 종목 이름을 쓰지 않는다** — `운동 시작`, `이번 주 운동`. 종목이 늘어날 예정이라 이름은 운동을 고르는 자리가 생길 때 붙는다 |

## 6. Workout (운동 화면) — 핵심

### 6.1 레이아웃

| ID | 요구사항 |
|---|---|
| FR-WRK-01 🔁 ⚠ | 프리뷰는 **화면 폭 전부 · 3:4 · 상단 고정**이다. 세로 공간을 더 줘도 커지지 않는다(가로가 먼저 막힌다) |
| FR-WRK-02 🔁 ⚠ | **3:4는 모델이 정한 값이다.** 입력이 192×256이라 letterbox 패딩이 0이다. 16:9로 바꾸면 가로를 75%만 쓰고 **정면 판정(전부 수평 측정)의 임계값 근거가 흔들린다** |
| FR-WRK-03 🔁 | 프리뷰 아래는 **스크롤**이다 — 안내가 길어지면 버튼이 잘린다 |
| FR-WRK-04 🔁 | HUD: 좌상단 나가기 · 우상단 `동작 예시`·카메라 전환 · 중앙 rep 숫자 · 하단 피드백 스택 · 하단 컨트롤 줄 |
| FR-WRK-05 🔁 ⚠ | **하단 컨트롤 줄에는 지금 할 일만 둔다** — `기준 자세 재기` → `운동 종료`. 동작 예시를 여기 넣지 않는다 |

### 6.2 카메라

| ID | 요구사항 |
|---|---|
| FR-WRK-06 🔁 | 전/후면 전환. 기본은 후면 |
| FR-WRK-07 🔁 ⚠ | **추론은 좌우 반전 없이** 한다. 반전된 프레임을 넣으면 모델의 좌/우 라벨이 뒤집혀 무릎 판정이 **조용히** 틀린다 |
| FR-WRK-08 🔁 | 전면 카메라일 때는 **그릴 때만** 좌표를 뒤집는다 (오버레이의 `mirrored`) |
| FR-WRK-09 🔁 | 분석 해상도는 480×640 기준. 프레임이 밀리면 **최신 프레임만** 처리하고 나머지는 버린다 |
| FR-WRK-10 🆕 ⚠ | 회전 보정은 **카메라 레이어가 한다.** 직접 회전시키면 프레임마다 버퍼를 새로 만들어 GC/메모리 압박이 생긴다 (Android 실측: 회전 단계 p95 3.21ms + 300프레임당 GC 3회가 사라짐) |
| FR-WRK-11 🆕 | 카메라 세션 인터럽션(전화·다른 앱·화면 분할)에서 복구한다 |
| FR-WRK-12 🆕 | 운동 중 **화면이 꺼지지 않게** 한다 (`isIdleTimerDisabled`). 화면을 나가면 반드시 되돌린다 |

### 6.3 권한

| ID | 요구사항 |
|---|---|
| FR-WRK-13 🔁 | 권한이 없으면 요청한다. 거부돼도 앱은 죽지 않는다 |
| FR-WRK-14 🆕 | iOS는 **두 번째 요청이 불가능하다.** 거부 상태면 "설정에서 카메라를 켜 주세요" + 설정 앱으로 보내는 버튼을 둔다 |

### 6.4 안내 순서 (겹치면 안 된다)

```
권한 → 동작 예시 시트(처음 1회) → 코치마크 → (사용자가 직접) 기준 자세 재기
```

| ID | 요구사항 |
|---|---|
| FR-WRK-15 🔁 ⚠ | **측정·카운팅 중에는 코치마크를 띄우지 않는다** |
| FR-WRK-16 🔁 | `동작 예시`는 처음 들어온 사람에게 자동으로 1회 뜨고, 이후에는 HUD 우상단 아이콘으로 언제든 연다 |
| FR-WRK-17 🔁 | 동작 예시는 **정면/측면으로 나누지 않는다**(예시가 사선 촬영이고 방향은 앱이 판별한다). 영상 위에 관절선·수치를 얹지 않는다 |

### 6.5 기준 자세(calibration)

| ID | 요구사항 |
|---|---|
| FR-WRK-18 🔁 | `기준 자세 재기` → 준비 시간 카운트다운(설정값) → **약 3초 측정** → 완료 |
| FR-WRK-19 🔁 | 준비 시간 동안 **지금 관절이 다 보이는지**를 표시한다 — 카운트다운이 끝나기 전에 위치를 고칠 수 있어야 한다 |
| FR-WRK-20 🔁 ⚠ | **준비 자세 점검(5종)을 통과해야 측정이 시작된다.** 막는 항목이 오탐하면 사용자가 앱을 아예 쓸 수 없다 |
| FR-WRK-21 🔁 | 측정 실패 사유를 문구로 말한다: 시간이 짧음 / 너무 작게 나옴 / 움직임 / 무릎 안 펴짐 / 비스듬함 |
| FR-WRK-22 🔁 | **발이 안 보이는 것은 막지 않는다** — 발 관련 항목만 기록되지 않는다고 알린다 |
| FR-WRK-23 🔁 | 촬영 방향(정면/측면)은 **측정 창의 다수결로 자동 판별**한다. 사용자용 화면에 선택 버튼이 없다 |
| FR-WRK-24 🔁 ⚠ | **프레임 단위로 판별하지 않는다.** 실측 오분류 0.5%가 rep 안에서 판정을 뒤집는다. 45°면 "비스듬하다"로 측정을 막는다 |

### 6.6 카운팅

| ID | 요구사항 |
|---|---|
| FR-WRK-25 🔁 ⚠ | **기준 자세를 다 잰 뒤에만 센다.** 걸어가며 자리를 잡는 동안 유령 rep이 세어지던 문제 때문 |
| FR-WRK-26 🔁 | 안 세는 동안 **왜 안 세는지를 숫자 바로 아래에** 알린다 (`먼저 기준 자세를 재주세요`) |
| FR-WRK-27 🔁 | rep 숫자는 2자리까지 96pt, 3자리부터 72pt. 증가할 때 펄스 |
| FR-WRK-28 🔁 | 촬영 방향이 바뀌면 기준선이 무효가 되고 카운팅도 멈춘다 |

### 6.7 피드백 표시

| ID | 요구사항 |
|---|---|
| FR-WRK-29 🔁 ⚠ | 경고는 **항목당 2초 붙잡는다.** 최저점에서 난 경고를 다 올라온 뒤에 읽을 수 있어야 한다(상승 p95 1,171ms) |
| FR-WRK-30 🔁 ⚠ | **항목마다 시간을 다르게 두지 않는다** |
| FR-WRK-31 🔁 ⚠ | 붙잡힌 항목을 **전부** 그린다. 정렬은 **도착 순(새 것이 맨 위)** — 우선순위 순이 아니다 |
| FR-WRK-32 🔁 | 같은 프레임에 함께 나면 그때만 선언 순서로 가른다 |

### 6.8 종료

| ID | 요구사항 |
|---|---|
| FR-WRK-33 🔁 ⚠ | **0회로 끝낸 세션은 저장하지 않는다.** 사용자에게는 기록이 아니라 잘못 누른 흔적이다 |

## 14. 수용 기준 (출시 전 손으로 확인하는 것)

1. 기준 자세를 재지 않고 스쿼트를 해도 **숫자가 0에서 움직이지 않고**, 왜 안 세는지가 숫자 아래에 있다.
2. 한 세트를 끝내면 rep 숫자와 결과 화면의 `총 횟수`가 같다.
3. 측면으로만 찍은 세션의 결과 화면에 **"무릎 관련 항목은 보지 못했다"**는 문장이 있다.
4. 0회로 종료하면 기록 목록과 홈의 세션 수가 **변하지 않는다**.
5. 비행기모드에서 전 과정이 동작한다.
6. 운동 중 전화를 받고 돌아와도 앱이 살아 있다.
7. 운동 중 화면이 자동으로 꺼지지 않는다.
8. 결과 화면에서 피드백이 길어도 `홈으로` 버튼이 **항상 보인다**.
9. 기록 카드 어디에도 날짜가 중복으로 적혀 있지 않다.
10. 화면 어디에도 `rep`·`SIDE`·`valgus`·임계값 숫자가 보이지 않는다.
